1Auto Scaling Groups, launch templates, scaling policies

Launch template — the blueprint an ASG stamps out
aws ec2 create-launch-template \
  --launch-template-name roadmap-web-lt \
  --launch-template-data '{
    "ImageId": "ami-xxxxxxxx", "InstanceType": "t3.micro",
    "SecurityGroupIds": ["sg-xxxx"]
  }'
Auto Scaling Group across two AZs
aws autoscaling create-auto-scaling-group \
  --auto-scaling-group-name roadmap-web-asg \
  --launch-template LaunchTemplateName=roadmap-web-lt,Version='$Latest' \
  --min-size 2 --max-size 6 --desired-capacity 2 \
  --vpc-zone-identifier "subnet-aaaa,subnet-bbbb"
A target-tracking scaling policy — let AWS do the math
aws autoscaling put-scaling-policy \
  --auto-scaling-group-name roadmap-web-asg \
  --policy-name cpu-target-tracking \
  --policy-type TargetTrackingScaling \
  --target-tracking-configuration '{
    "PredefinedMetricSpecification": {"PredefinedMetricType": "ASGAverageCPUUtilization"},
    "TargetValue": 50.0
  }'
Checkpoint

Load-test the group (even a crude while true; do curl ...; done loop from a few terminals) and watch aws autoscaling describe-scaling-activities show it actually adding instances, then scaling back down once load stops.

2Application and Network Load Balancers, target groups, health checks

Target group with a real health check
aws elbv2 create-target-group \
  --name roadmap-web-tg --protocol HTTP --port 80 --vpc-id vpc-xxxx \
  --health-check-path /healthz --health-check-interval-seconds 15 \
  --healthy-threshold-count 2 --unhealthy-threshold-count 3
Application Load Balancer, listener, and attaching the ASG
aws elbv2 create-load-balancer \
  --name roadmap-alb --subnets subnet-aaaa subnet-bbbb \
  --security-groups sg-xxxx

aws elbv2 create-listener \
  --load-balancer-arn <ALB_ARN> --protocol HTTP --port 80 \
  --default-actions Type=forward,TargetGroupArn=<TG_ARN>

aws autoscaling attach-load-balancer-target-groups \
  --auto-scaling-group-name roadmap-web-asg --target-group-arns <TG_ARN>

ALB operates at layer 7 (HTTP/HTTPS) — it can route on path or host header. NLB operates at layer 4 (TCP/UDP) — it's for raw throughput and static IPs, not content-aware routing. Pick ALB unless you specifically need NLB's characteristics.

Common trap

A target failing health checks doesn't get an error in the ALB — it silently stops receiving traffic. Always check aws elbv2 describe-target-health first when "the load balancer isn't working."
