1Modules, workspaces, remote state with S3 + DynamoDB locking

A reusable module structure
modules/vpc/
  main.tf        # resources
  variables.tf   # inputs
  outputs.tf     # what callers can reference

# root main.tf calling it:
module "vpc" {
  source   = "./modules/vpc"
  cidr_block = "10.0.0.0/16"
}
Workspaces — one config, multiple isolated state files
terraform workspace new staging
terraform workspace new production
terraform workspace select staging
terraform apply    # applies against staging's own state, isolated from production
Remote state in S3 with DynamoDB locking
terraform {
  backend "s3" {
    bucket         = "roadmap-tfstate-<yourname>"
    key            = "capstone/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "terraform-locks"
    encrypt        = true
  }
}
Provision the backend itself first (a classic chicken-and-egg -- do this once, manually)
aws s3api create-bucket --bucket roadmap-tfstate-<yourname>
aws s3api put-bucket-versioning --bucket roadmap-tfstate-<yourname> \
  --versioning-configuration Status=Enabled
aws dynamodb create-table --table-name terraform-locks \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
Checkpoint

Run terraform apply from two terminals at once and confirm the second one blocks on the DynamoDB lock instead of corrupting state — that's the entire reason the lock table exists.

2Refactor Week 9's hand-built VPC into a reusable Terraform module

Take the VPC you built by hand with the CLI in Week 9 — public/private subnets, IGW, NAT, route tables — and express it as a Terraform module with variables for CIDR blocks and AZ count, so it can be re-applied to build identical VPCs for staging and production.

Sketch of the module's variables
variable "vpc_cidr"        { type = string }
variable "az_count"        { type = number, default = 2 }
variable "environment"     { type = string }   # "staging" | "production"
Checkpoint

Destroy the hand-built VPC entirely, then terraform apply the module and confirm the resulting VPC is functionally identical — same subnet layout, same route tables, same NAT behavior.
