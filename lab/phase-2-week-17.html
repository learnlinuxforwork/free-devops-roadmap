1KMS envelope encryption, Secrets Manager vs Parameter Store

Create a key, then see envelope encryption in action
aws kms create-key --description "roadmap-app-key"
aws kms create-alias --alias-name alias/roadmap-app --target-key-id <KEY_ID>

# Envelope encryption: KMS generates a data key, you encrypt your data with it locally,
# then KMS encrypts the data key itself -- only the tiny encrypted key ever needs a KMS call
aws kms generate-data-key --key-id alias/roadmap-app --key-spec AES_256
Secrets Manager — for secrets that need rotation
aws secretsmanager create-secret --name roadmap/db-password \
  --secret-string '{"username":"app","password":"<STRONG_PASSWORD>"}'
aws secretsmanager rotate-secret --secret-id roadmap/db-password \
  --rotation-lambda-arn <LAMBDA_ARN> --rotation-rules AutomaticallyAfterDays=30
Parameter Store — for config and secrets that don't need built-in rotation
aws ssm put-parameter --name /roadmap/api-timeout --value "30" --type String
aws ssm put-parameter --name /roadmap/api-key --value "<KEY>" --type SecureString
aws ssm get-parameter --name /roadmap/api-key --with-decryption

Rule of thumb for the exam: if it needs automatic rotation (database credentials, API keys with a rotation Lambda), reach for Secrets Manager. For everything else — feature flags, simple config values, secrets you'll rotate manually — Parameter Store is free and simpler.

2IAM policy deep dive: conditions, permission boundaries, SCPs

A condition — deny anything outside your office IP range
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Deny", "Action": "*", "Resource": "*",
    "Condition": {"NotIpAddress": {"aws:SourceIp": "203.0.113.0/24"}}
  }]
}
Permission boundary — a ceiling on what a role can ever be granted, even by future policy edits
aws iam create-role --role-name DevSandboxRole \
  --assume-role-policy-document file://trust-policy.json \
  --permissions-boundary arn:aws:iam::<ACCOUNT_ID>:policy/MaxDevPermissions
Service Control Policy — an org-wide ceiling across every account in an OU
aws organizations create-policy \
  --name "DenyRegionsOutsideUS" --type SERVICE_CONTROL_POLICY \
  --content file://deny-other-regions-scp.json
aws organizations attach-policy --policy-id p-xxxx --target-id ou-xxxx
Common trap

A permission boundary or SCP that denies an action wins even if an identity policy explicitly allows it — the effective permission is always the intersection, never just the most generous policy in the stack.
