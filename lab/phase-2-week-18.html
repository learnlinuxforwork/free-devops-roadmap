1Lambda (cold starts, concurrency, layers), API Gateway

Create a function and control concurrency
aws lambda create-function --function-name roadmap-api \
  --runtime python3.13 --handler app.handler \
  --role arn:aws:iam::<ACCOUNT_ID>:role/roadmap-lambda-role \
  --zip-file fileb://function.zip

# Reserved concurrency caps how many run at once -- protects downstream systems
aws lambda put-function-concurrency \
  --function-name roadmap-api --reserved-concurrent-executions 10

# Provisioned concurrency keeps N instances warm -- eliminates cold starts for that many
aws lambda put-provisioned-concurrency-config \
  --function-name roadmap-api --qualifier '$LATEST' --provisioned-concurrent-executions 2
Layers — share dependencies across functions without bundling them each time
aws lambda publish-layer-version --layer-name roadmap-shared-deps \
  --zip-file fileb://layer.zip --compatible-runtimes python3.13
API Gateway HTTP API in front of it
aws apigatewayv2 create-api --name roadmap-http-api \
  --protocol-type HTTP --target arn:aws:lambda:us-east-1:<ACCOUNT_ID>:function:roadmap-api

A cold start happens when Lambda has to initialize a new execution environment — download the code, start the runtime, run init code — before it can handle your request. Provisioned concurrency trades cost for eliminating that latency on a guaranteed number of instances.

2Step Functions and EventBridge; build a small event-driven app

A state machine in Amazon States Language
{
  "Comment": "Process an order",
  "StartAt": "ValidateOrder",
  "States": {
    "ValidateOrder": {"Type": "Task", "Resource": "arn:aws:lambda:...:validate",
      "Next": "ChargePayment"},
    "ChargePayment": {"Type": "Task", "Resource": "arn:aws:lambda:...:charge",
      "Catch": [{"ErrorEquals": ["States.ALL"], "Next": "RefundOrder"}],
      "Next": "ShipOrder"},
    "ShipOrder": {"Type": "Task", "Resource": "arn:aws:lambda:...:ship", "End": true},
    "RefundOrder": {"Type": "Task", "Resource": "arn:aws:lambda:...:refund", "End": true}
  }
}
Create it, and wire an EventBridge rule to trigger it on a schedule or an event
aws stepfunctions create-state-machine \
  --name roadmap-order-flow --definition file://state-machine.json \
  --role-arn arn:aws:iam::<ACCOUNT_ID>:role/roadmap-sfn-role

aws events put-rule --name new-order-rule \
  --event-pattern '{"source": ["roadmap.orders"], "detail-type": ["OrderPlaced"]}'
aws events put-targets --rule new-order-rule \
  --targets "Id"="1","Arn"="<STATE_MACHINE_ARN>","RoleArn"="<EVENTBRIDGE_ROLE_ARN>"
Checkpoint

Publish a test event to EventBridge and watch it trigger the Step Functions execution end to end in the console's visual workflow graph — including the Catch branch, by making the charge step fail on purpose once.
