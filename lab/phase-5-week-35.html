1Trunk-based development vs GitFlow; pipeline stages (build/test/deploy)

Trunk-based — short-lived branches, merge to main constantly
git checkout -b fix/rate-limit-bug main
# small change, done within hours, not days
git push -u origin fix/rate-limit-bug
gh pr create --base main
# merge same day -- feature flags (Week 38) hide unfinished work, not long-lived branches
GitFlow — heavier, longer-lived branches for scheduled releases
main          # production-only, tagged releases
develop       # integration branch
feature/*     # branched from develop, merged back to develop
release/*     # cut from develop, stabilized, merged to both main and develop
hotfix/*      # branched from main for urgent production fixes

Trunk-based fits the continuous-deploy pattern this roadmap builds toward — it needs strong automated testing and feature flags to be safe. GitFlow fits teams shipping on a scheduled release cadence (mobile app stores, regulated environments) where a stabilization branch is genuinely useful.

Pipeline stages — the shape every CI/CD tool in this phase implements
build   -> compile/package, produce an immutable artifact (a container image, tagged by commit SHA)
test    -> run the testing pyramid below against that artifact
deploy  -> promote the SAME artifact through environments (dev -> staging -> prod)
         -- never rebuild between environments; that's how "works in staging" bugs sneak in

2Testing pyramid: unit, integration, contract, smoke tests

The pyramid, bottom to top — quantity should shrink as scope grows
Unit tests         Fast, no network/DB, test one function/class in isolation. Hundreds-thousands.
Integration tests   Real DB/queue, test how components work together. Dozens-hundreds.
Contract tests      Verify a service's API matches what its consumers expect. Per integration point.
E2E/smoke tests     Full stack, real environment, just enough to prove "it's not on fire." Few.
A pytest unit test for the Week 6 log parser
def test_counts_status_codes():
    line = '"GET / HTTP/1.1" 200'
    assert extract_status(line) == "200"

def test_ignores_malformed_lines():
    assert extract_status("garbage") is None
A smoke test run right after every deploy, before declaring success
#!/usr/bin/env bash
set -euo pipefail
STATUS=$(curl -s -o /dev/null -w "%{http_code}" https://api.roadmap.example.com/healthz)
[ "$STATUS" = "200" ] || { echo "Smoke test failed: got $STATUS"; exit 1; }
echo "Smoke test passed"
Common trap

An inverted pyramid — few unit tests, heavy reliance on slow E2E tests — is the single most common reason a team's CI takes 40 minutes and still misses bugs. Push coverage down the pyramid wherever the test doesn't genuinely need the full stack.
