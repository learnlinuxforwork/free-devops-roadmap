1Build a custom VPC: public/private subnets, route tables, IGW/NAT

VPC and subnets
aws ec2 create-vpc --cidr-block 10.0.0.0/16 --query 'Vpc.VpcId' --output text
aws ec2 create-subnet --vpc-id vpc-xxxx --cidr-block 10.0.1.0/24 --availability-zone us-east-1a   # public
aws ec2 create-subnet --vpc-id vpc-xxxx --cidr-block 10.0.2.0/24 --availability-zone us-east-1b   # private
Internet gateway for the public subnet
aws ec2 create-internet-gateway --query 'InternetGateway.InternetGatewayId' --output text
aws ec2 attach-internet-gateway --vpc-id vpc-xxxx --internet-gateway-id igw-xxxx

aws ec2 create-route-table --vpc-id vpc-xxxx --query 'RouteTable.RouteTableId' --output text
aws ec2 create-route --route-table-id rtb-public \
  --destination-cidr-block 0.0.0.0/0 --gateway-id igw-xxxx
aws ec2 associate-route-table --route-table-id rtb-public --subnet-id subnet-public
NAT gateway so the private subnet can reach the internet outbound only
aws ec2 allocate-address --domain vpc --query 'AllocationId' --output text
aws ec2 create-nat-gateway --subnet-id subnet-public --allocation-id eipalloc-xxxx

aws ec2 create-route-table --vpc-id vpc-xxxx --query 'RouteTable.RouteTableId' --output text
aws ec2 create-route --route-table-id rtb-private \
  --destination-cidr-block 0.0.0.0/0 --nat-gateway-id nat-xxxx
aws ec2 associate-route-table --route-table-id rtb-private --subnet-id subnet-private
Checkpoint

An EC2 instance in the private subnet can curl the internet (outbound via NAT) but has no public IP and can't be reached from outside. An instance in the public subnet can do both.

2Security groups vs NACLs; VPC peering basics

Security groups — stateful, attached to instances
aws ec2 create-security-group --group-name web-sg --vpc-id vpc-xxxx --description "web tier"
aws ec2 authorize-security-group-ingress --group-id sg-xxxx \
  --protocol tcp --port 443 --cidr 0.0.0.0/0
# Return traffic is automatically allowed -- that's what "stateful" means
Network ACLs — stateless, attached to subnets
aws ec2 create-network-acl --vpc-id vpc-xxxx
aws ec2 create-network-acl-entry --network-acl-id acl-xxxx \
  --rule-number 100 --protocol tcp --port-range From=443,To=443 \
  --cidr-block 0.0.0.0/0 --rule-action allow --ingress
aws ec2 create-network-acl-entry --network-acl-id acl-xxxx \
  --rule-number 100 --protocol tcp --port-range From=1024,To=65535 \
  --cidr-block 0.0.0.0/0 --rule-action allow --egress
# Stateless means you must explicitly allow the ephemeral-port return traffic yourself
VPC peering
aws ec2 create-vpc-peering-connection \
  --vpc-id vpc-aaaa --peer-vpc-id vpc-bbbb
aws ec2 accept-vpc-peering-connection --vpc-peering-connection-id pcx-xxxx
# Then add routes in BOTH route tables pointing at the peering connection
Common trap

The RHCSA-style exam trap here is symmetric: forgetting the NACL's egress rule for ephemeral return ports is the classic reason a security-group-allowed request still times out.

3Diagram your VPC — keep it for your portfolio

Draw the VPC exactly as you built it: CIDR block, both subnets with their CIDRs and AZs, the IGW, the NAT gateway, both route tables with their routes, and which resources sit in which subnet. This single diagram is one of the most reused artifacts in your portfolio — you'll redraw variations of it in Phases 2, 3, and 8.

Checkpoint

Export the diagram as SVG or PNG and commit it to docs/architecture/vpc.svg in your capstone repo from Week 5.
