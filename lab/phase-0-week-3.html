1Partitions, LVM, filesystems, /etc/fstab, swap

Partitioning with parted (GPT-safe, scriptable)
lsblk                                 # see all block devices
parted /dev/sdb print
parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart primary 0% 100%
partprobe /dev/sdb                    # tell the kernel to re-read the partition table
LVM — physical volume to logical volume
pvcreate /dev/sdb1
vgcreate vg_data /dev/sdb1
lvcreate -n lv_app -L 20G vg_data
mkfs.xfs /dev/vg_data/lv_app

# Growing a logical volume later:
lvextend -L +10G /dev/vg_data/lv_app
xfs_growfs /dev/vg_data/lv_app        # xfs; use resize2fs for ext4

pvs; vgs; lvs                          # summary at each layer
Mounting and /etc/fstab
mkdir -p /data
mount /dev/vg_data/lv_app /data
blkid /dev/vg_data/lv_app             # get the UUID

# /etc/fstab — always mount by UUID, device names can shift
UUID=3a1f...  /data  xfs  defaults  0 0

mount -a                               # test fstab without rebooting — catches typos now, not at boot
Swap
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
swapon --show

# /etc/fstab entry to make it persistent:
/swapfile  none  swap  sw  0 0
Common trap

A bad UUID or typo in /etc/fstab can drop the system into emergency mode on next boot. Always run mount -a after editing it, and know the rd.break recovery flow from Week 1 in case you do get it wrong.

2NetworkManager/nmcli, static IPs, DNS, routing, firewalld

nmcli basics
nmcli device status
nmcli connection show
nmcli connection show "System eth0"    # full detail on one connection
nmcli device show eth0
Setting a static IP
nmcli con add type ethernet con-name static-eth0 ifname eth0 \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "1.1.1.1 8.8.8.8" \
  ipv4.method manual

nmcli con up static-eth0

# Modifying an existing connection instead of creating a new one:
nmcli con mod "System eth0" ipv4.addresses 192.168.1.50/24
nmcli con mod "System eth0" ipv4.method manual
nmcli con up "System eth0"
Routing
ip route show
nmcli con mod "System eth0" +ipv4.routes "10.10.0.0/16 192.168.1.254"
ip route add 10.10.0.0/16 via 192.168.1.254   # non-persistent, testing only
firewalld
firewall-cmd --state
firewall-cmd --get-active-zones
firewall-cmd --list-all
firewall-cmd --add-service=http --permanent
firewall-cmd --add-port=8080/tcp --permanent
firewall-cmd --reload                          # required for --permanent changes to take effect
firewall-cmd --list-services
firewall-cmd --zone=public --add-source=10.0.0.0/8 --permanent
Checkpoint

Configure a static IP with nmcli, confirm it survives a reboot, then open port 8443/tcp in firewalld permanently and verify with firewall-cmd --list-ports.

3SELinux modes, contexts, booleans, and troubleshooting denials

Modes
getenforce                  # Enforcing, Permissive, or Disabled
setenforce 0                # switch to Permissive (temporary, until reboot)
setenforce 1                # back to Enforcing

# /etc/selinux/config — controls the mode on boot
SELINUX=enforcing
SELINUXTYPE=targeted
Contexts
ls -Z /var/www/html                 # show SELinux context on files
ps -eZ | grep httpd                 # show context on running processes

# Fix a mislabeled file (e.g. content copied instead of moved into place):
semanage fcontext -a -t httpd_sys_content_t "/srv/web(/.*)?"
restorecon -Rv /srv/web             # apply the policy you just defined
Booleans — policy toggles without writing custom policy
getsebool -a | grep httpd
getsebool httpd_can_network_connect
setsebool httpd_can_network_connect on          # temporary
setsebool -P httpd_can_network_connect on       # persistent across reboots
Troubleshooting denials
sudo ausearch -m avc -ts recent          # recent denials, human-ish readable
sudo ausearch -m avc -ts today | audit2why    # explain *why* it was denied

# If the denial is legitimate for your use case, generate a custom policy module:
sudo ausearch -m avc -ts recent | audit2allow -M myapp
sudo semodule -i myapp.pp                # install the generated module

sudo semodule -l | grep myapp             # confirm it loaded
Common trap

Never leave a production system in Permissive mode "to make the error go away." That disables SELinux enforcement system-wide. Fix the context or write a targeted policy module instead — treat SELinux denials as information, not an obstacle.

4TCP/IP and subnetting; curl, dig, traceroute, ss

Subnetting — the fast way to read CIDR
/24  = 255.255.255.0    = 256 addresses (254 usable)
/25  = 255.255.255.128  = 128 addresses (126 usable)
/26  = 255.255.255.192  = 64 addresses  (62 usable)
/27  = 255.255.255.224  = 32 addresses  (30 usable)
/28  = 255.255.255.240  = 16 addresses  (14 usable)

# 192.168.1.0/26 splits into 4 blocks of 64:
# 192.168.1.0/26   hosts .1-.62    broadcast .63
# 192.168.1.64/26  hosts .65-.126  broadcast .127
# 192.168.1.128/26 hosts .129-.190 broadcast .191
# 192.168.1.192/26 hosts .193-.254 broadcast .255
curl
curl -I https://example.com                 # headers only
curl -v https://example.com                 # verbose — see the full request/response
curl -X POST -H "Content-Type: application/json" \
  -d '{"key":"value"}' https://example.com/api
curl -o out.html https://example.com        # save to a file
curl -w "%{http_code}\n" -o /dev/null -s https://example.com   # status code only
dig
dig example.com
dig +short example.com              # just the answer
dig example.com MX                   # mail records
dig -x 8.8.8.8                       # reverse lookup
dig @1.1.1.1 example.com             # query a specific resolver
traceroute and ss
traceroute example.com
traceroute -n example.com           # skip reverse DNS on each hop, faster

ss -tulpn                            # listening TCP/UDP sockets, with process names
ss -s                                # socket summary statistics
ss -tan state established            # only established TCP connections
Checkpoint

Given a network of 10.20.0.0/22, calculate by hand how many usable hosts it holds and what the broadcast address is, without a subnet calculator. This comes up constantly once you're designing VPCs in Phase 1.
