1Deploy kube-prometheus-stack on your EKS cluster

Install via Helm
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install monitoring prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace
Confirm it's scraping your capstone app
kubectl get pods -n monitoring
kubectl port-forward -n monitoring svc/monitoring-kube-prometheus-prometheus 9090:9090
# open http://localhost:9090, query: up{namespace="roadmap"}
A ServiceMonitor so Prometheus discovers the capstone app automatically
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata: { name: roadmap-api, namespace: monitoring }
spec:
  selector: { matchLabels: { app: roadmap-api } }
  namespaceSelector: { matchNames: [roadmap] }
  endpoints:
    - port: metrics
      path: /metrics
Common trap

A ServiceMonitor with the wrong matchLabels silently discovers nothing — no error, just an empty target list in Prometheus. Always confirm in the Prometheus UI's Targets page, don't just trust the YAML applied cleanly.

2Build a Grafana dashboard for the capstone app's key metrics

Get the auto-provisioned Grafana password and open it
kubectl get secret -n monitoring monitoring-grafana \
  -o jsonpath='{.data.admin-password}' | base64 -d
kubectl port-forward -n monitoring svc/monitoring-grafana 3000:80
A PromQL query for the panel — p95 request latency
histogram_quantile(0.95,
  sum(rate(http_request_duration_seconds_bucket{namespace="roadmap"}[5m])) by (le)
)
And one for error rate as a percentage
sum(rate(http_requests_total{namespace="roadmap",status=~"5.."}[5m]))
/
sum(rate(http_requests_total{namespace="roadmap"}[5m])) * 100
Checkpoint

Build a dashboard with request rate, p95 latency, and error rate side by side — the three metrics that answer 'is the app healthy' faster than anything else. You'll define SLOs against exactly these in Week 44.
