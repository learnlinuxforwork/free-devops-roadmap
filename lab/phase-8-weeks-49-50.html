1Full stack: Terraform-provisioned VPC → EKS → containerized microservices → CI/CD → monitoring

This is every phase of the roadmap operating as one system, not a checklist review. Walk the full chain end to end and fix whatever's drifted: Terraform apply from a clean checkout, EKS healthy, the GitOps pipeline deploying on push, dashboards showing real traffic, alarms wired to something that actually notifies you.

A single end-to-end verification pass
cd infra && terraform init && terraform plan     # should show zero unexpected drift
kubectl get pods -n roadmap -o wide
kubectl get hpa,pdb -n roadmap
curl -s https://api.roadmap.<yourdomain>/healthz
# push a trivial commit and time how long it takes to reach production automatically
git commit --allow-empty -m "chore: verify pipeline" && git push
Checkpoint

If anything in this chain requires a manual step you'd forget under pressure, fix it now — Phase 8 is not the week to discover a gap in the automation.

3Publish the repo publicly — this is your interview artifact

Final pre-publish checklist
grep -rniE 'password|secret|api[_-]?key' --include='*.tf' --include='*.yaml' . \
  | grep -v 'variable\|description'   # scan for anything that looks like a leaked credential

cat .gitignore   # confirm terraform.tfstate, .env, *.pem are all excluded

git log --all --full-history -- '*.pem' '*.env'   # confirm none were EVER committed, even in old commits
Make it public
gh repo edit <you>/capstone-project --visibility public --accept-visibility-change-consequences
Common trap

A secret committed and later deleted is still in Git history forever unless you rewrite history (git filter-repo) — deleting the file in a new commit does not remove it from the repo. Scan history, not just the current working tree, before flipping to public.
