1AWS CDK overview (Python or TypeScript)

A CDK stack in Python — real code generates the template for you
from aws_cdk import Stack, aws_ec2 as ec2
from constructs import Construct

class RoadmapStack(Stack):
    def __init__(self, scope: Construct, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)
        vpc = ec2.Vpc(self, "RoadmapVpc", max_azs=2)
        ec2.Instance(self, "WebInstance",
            vpc=vpc,
            instance_type=ec2.InstanceType("t3.micro"),
            machine_image=ec2.MachineImage.latest_amazon_linux2023(),
        )
CDK workflow
cdk bootstrap                # one-time per account/region setup
cdk synth                     # generate the underlying CloudFormation template
cdk diff                      # like terraform plan
cdk deploy                    # like terraform apply

CDK isn't a fourth competing format — it compiles down to CloudFormation templates under the hood. The value is writing infrastructure in a real programming language: loops, conditionals, functions, and your editor's type checking, instead of a templating language.

2Write a one-pager: when to choose Terraform vs CloudFormation vs CDK

A decision framework to start from
Choose Terraform when:      multi-cloud is a real requirement, or the team already knows it
Choose CloudFormation when:  AWS-only, want zero extra tooling/state management
Choose CDK when:             AWS-only, team is strong in Python/TypeScript, complex conditional logic
Checkpoint

Commit the one-pager to docs/architecture/iac-tool-choice.md in your capstone repo, and state explicitly which tool you're using for the Week 25 capstone build and why — this becomes a real interview talking point.
