1Sit a full timed, hands-on RHCSA mock exam — no notes, no internet

The real EX200 is 2.5–3 hours of performance-based tasks on a live system — no multiple choice. Run your mock exam under the same conditions: timer running, notes closed, browser closed except the exam itself.

Official RHCSA (EX200) objective categories — score yourself against each
Understand and use essential tools
  - Log in/out, use shell, redirection, pipes, remote systems (ssh)
  - Archive, compress, unpack files (tar, gzip, xz)
  - Search, edit text files, cron/anacron

Create simple shell scripts
  - Loops, conditionals, positional parameters, exit codes

Operate running systems
  - Boot, reboot, targets, single-user mode, kill/signal processes
  - Locate and analyze log files, systemctl start/stop/enable/status

Configure local storage
  - Partitions, LVM, encrypted volumes, mount at boot or on demand

Create and configure file systems
  - ext4, xfs, swap, /etc/fstab, autofs, ACLs

Deploy, configure, and maintain systems
  - Package installation, network services, cron, time sync

Manage users and groups
  - useradd/usermod, sudo, password policy, /etc/skel

Manage security
  - Firewalld, SELinux modes/contexts/booleans, SSH key-based auth
Structure your own mock exam
# Write 20-24 tasks, one or two per objective category above, e.g.:
1. Set the system hostname and update /etc/hosts
2. Create an LVM volume group spanning two disks, 15GB logical volume, ext4, mounted at /projects, persistent
3. Create a user with UID 1500, add to group 'ops', force password change at first login
4. Configure a cron job as that user running every weekday at 6am
5. Open TCP port 8080 permanently in firewalld
6. Fix a provided SELinux denial on a web directory
7. Create a bash script that takes a filename argument and reports if it's a broken symlink
...
# Time-box it at 2.5-3 hours. Stop when the timer ends, whether or not you're done —
# that's real information about where you stand.
Checkpoint

Finish a full mock under time pressure and self-score it honestly against the objective list above before looking anything up.

2Score it, log every missed objective, rebuild those labs from scratch

This is where the real learning happens — not in taking the exam, but in the post-mortem. Keep a break/fix log, ideally the same one you started in Week 1 and will move into Git in Week 5.

Break/fix log entry format
## 2026-07-25 — Mock exam #1 — Score: 15/22 objectives

### Missed: LVM volume group spanning two disks
- What I did wrong: only added one physical volume to the VG
- Root cause: forgot `vgextend` exists — assumed vgcreate takes multiple devices, and it does,
  but I'd only prepped one PV with pvcreate before running vgcreate
- Fix: pvcreate /dev/sdb1 /dev/sdc1 && vgcreate vg_data /dev/sdb1 /dev/sdc1
- Rebuilt from scratch: yes, 3 times, until it was automatic

### Missed: SELinux denial on custom web directory
- What I did wrong: used chmod 777 to "fix" a permission-looking error that was actually SELinux
- Root cause: didn't check `ausearch -m avc -ts recent` first
- Fix: semanage fcontext -a -t httpd_sys_content_t "/srv/web(/.*)?" && restorecon -Rv /srv/web
- Rebuilt from scratch: yes, 2 times
Common trap

Don't just read the correct answer and move on. Tear down the lab environment and rebuild each missed objective from a blank system, from memory, at least twice. Recognition is not recall — the exam requires recall.

3Repeat a second mock at the end of the week; target a clean pass

Space the second mock at least 3-4 days after the first so the rebuild work has time to sink in. Use a different mock exam from linuxcert.guru if available, not the same one memorized.

Speed-drill: rehearse these until they take no thought
getenforce; setenforce 0; setenforce 1
systemctl enable --now sshd
useradd -m -G wheel newadmin && passwd newadmin
firewall-cmd --add-service=http --permanent && firewall-cmd --reload
pvcreate /dev/sdb1 && vgcreate vg1 /dev/sdb1 && lvcreate -n lv1 -L 5G vg1
mkfs.xfs /dev/vg1/lv1 && mkdir /data && mount /dev/vg1/lv1 /data
blkid /dev/vg1/lv1    # then add the UUID line to /etc/fstab, then: mount -a
crontab -e            # add: */5 * * * * /usr/local/bin/script.sh
chage -M 90 -W 7 newadmin
setfacl -m u:auditor:r /data/report.txt && getfacl /data/report.txt
Checkpoint

Pass the second mock at or above objective-mastery level — you should be scoring every category, not just most of them. If any single objective is still shaky, that's a half-day detour before Week 5, not something to carry forward.

4Optional: book the real EX200 for the end of Week 6

The RHCSA (EX200) is administered by Red Hat, either at a testing center or remotely via a proctored online exam. If your two mocks both score cleanly, book it now — a deadline on the calendar is a forcing function, and Week 5-6 content (Git, Bash/Python automation) doesn't require re-touching Phase 0 material.

Booking checklist
1. Create/sign in to a Red Hat account: redhat.com
2. Go to the Red Hat Certification portal and locate EX200
3. Choose a delivery method:
   - Individual exam at a Pearson VUE / Red Hat testing center
   - Online Exam Delivery (remote, proctored, needs a private room and ID)
4. Pick a date roughly 2-3 weeks out — enough runway, not so much you lose momentum
5. Read the current exam objectives PDF from Red Hat's site the week before —
   objectives do shift between RHEL major versions
Checkpoint

This step is optional but strongly recommended (see the cost note on the main roadmap). If you skip the real exam, still hold yourself to the same mock-exam bar before moving into Phase 1 — the AWS phases assume this Linux foundation is solid.
