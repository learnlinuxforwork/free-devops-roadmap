1Launch and connect to EC2 instances; AMIs and instance types

Find an AMI and launch an instance
aws ec2 describe-images --owners amazon \
  --filters "Name=name,Values=al2023-ami-*-x86_64" \
  --query 'Images | sort_by(@,&CreationDate) | [-1].ImageId' --output text

aws ec2 create-key-pair --key-name roadmap-key \
  --query 'KeyMaterial' --output text > roadmap-key.pem
chmod 400 roadmap-key.pem

aws ec2 run-instances \
  --image-id ami-xxxxxxxx --instance-type t3.micro \
  --key-name roadmap-key --security-groups default \
  --count 1 --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=roadmap-week8}]'
Connect
aws ec2 describe-instances --filters "Name=tag:Name,Values=roadmap-week8" \
  --query 'Reservations[].Instances[].PublicIpAddress' --output text

ssh -i roadmap-key.pem ec2-user@<PUBLIC_IP>

Instance types follow a family-generation-size pattern: t3.micro is burstable general purpose, m6i.large is fixed-performance general purpose, c7g.xlarge is compute-optimized on Graviton (ARM). The letter tells you the family, the number the generation, the suffix hints at the chip.

2S3 buckets, storage classes, versioning; EBS vs EFS

S3 basics
aws s3 mb s3://roadmap-capstone-<yourname>
aws s3api put-bucket-versioning \
  --bucket roadmap-capstone-<yourname> --versioning-configuration Status=Enabled
aws s3 cp report.pdf s3://roadmap-capstone-<yourname>/ --storage-class STANDARD_IA
aws s3 ls s3://roadmap-capstone-<yourname> --recursive
EBS — block storage attached to one instance
aws ec2 create-volume --availability-zone us-east-1a --size 20 --volume-type gp3
aws ec2 attach-volume --volume-id vol-xxxx --instance-id i-xxxx --device /dev/xvdf
EFS — shared network filesystem mountable by many instances
aws efs create-file-system --performance-mode generalPurpose
aws efs create-mount-target --file-system-id fs-xxxx \
  --subnet-id subnet-xxxx --security-groups sg-xxxx

# on the EC2 instance:
sudo mount -t efs fs-xxxx:/ /mnt/efs-share
Checkpoint

State from memory: EBS is single-instance block storage (like a virtual hard disk), EFS is multi-instance shared NFS storage, and S3 is object storage with no filesystem semantics at all — you don't mount it, you PUT and GET objects by key.

3Deploy a static site to S3 + CloudFront

Bucket + upload (kept private — CloudFront reads via Origin Access Control)
aws s3 mb s3://roadmap-static-site-<yourname>
aws s3 sync ./site s3://roadmap-static-site-<yourname>/ --delete
CloudFront distribution
aws cloudfront create-distribution \
  --origin-domain-name roadmap-static-site-<yourname>.s3.amazonaws.com \
  --default-root-object index.html
Invalidate the cache after a redeploy
aws cloudfront create-invalidation \
  --distribution-id EXXXXXXXXXXXX --paths "/*"
Common trap

Forgetting to invalidate the CloudFront cache after an S3 update is the single most common “why isn't my change showing up” moment in this stack. Cache TTLs default to 24 hours.
