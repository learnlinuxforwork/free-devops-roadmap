1Ingress controllers, ConfigMaps/Secrets, PersistentVolumes and Claims

An Ingress routing a hostname to the Service from Week 29
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: roadmap-ingress
  namespace: roadmap
spec:
  rules:
    - host: api.roadmap.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: roadmap-api
                port: { number: 80 }
ConfigMap and Secret — never bake config into the image
kubectl create configmap roadmap-config \
  --from-literal=LOG_LEVEL=info -n roadmap
kubectl create secret generic roadmap-db-creds \
  --from-literal=DATABASE_URL='postgres://app:app@db:5432/roadmap' -n roadmap
Reference them from the Deployment
        envFrom:
          - configMapRef: { name: roadmap-config }
          - secretRef: { name: roadmap-db-creds }
PersistentVolumeClaim — request durable storage without knowing the backend
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: roadmap-db-pvc, namespace: roadmap }
spec:
  accessModes: ["ReadWriteOnce"]
  resources: { requests: { storage: 10Gi } }
Common trap

Kubernetes Secrets are base64-encoded, not encrypted, by default — anyone with API read access to the namespace can decode them trivially. Treat them as access-controlled, not confidential, unless you've enabled encryption at rest.

2Namespaces and RBAC basics

A Role scoped to one namespace, and binding it to a user
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: roadmap-viewer, namespace: roadmap }
rules:
  - apiGroups: [""]
    resources: ["pods", "services"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: jordan-view, namespace: roadmap }
subjects:
  - kind: User
    name: jordan
roleRef:
  kind: Role
  name: roadmap-viewer
  apiGroup: rbac.authorization.k8s.io

A Role is namespace-scoped; a ClusterRole applies cluster-wide (or to a resource type that has no namespace, like Nodes). Same split as IAM policies scoped to one resource vs an account-wide policy — least privilege by default means reaching for Role first.

Checkpoint

Confirm the binding works with kubectl auth can-i list pods -n roadmap --as jordan and confirm it correctly denies kubectl auth can-i delete pods -n roadmap --as jordan.
