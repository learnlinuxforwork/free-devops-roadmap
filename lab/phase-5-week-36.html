1CodePipeline + CodeBuild + CodeDeploy end-to-end for the capstone app

buildspec.yml — what CodeBuild actually executes
version: 0.2
phases:
  pre_build:
    commands:
      - aws ecr get-login-password | docker login --username AWS --password-stdin $ECR_URI
  build:
    commands:
      - docker build -t $ECR_URI:$CODEBUILD_RESOLVED_SOURCE_VERSION .
  post_build:
    commands:
      - docker push $ECR_URI:$CODEBUILD_RESOLVED_SOURCE_VERSION
      - printf '[{"name":"api","imageUri":"%s"}]' $ECR_URI:$CODEBUILD_RESOLVED_SOURCE_VERSION > imagedefinitions.json
artifacts:
  files: [imagedefinitions.json]
Wire the three services into one pipeline
aws codepipeline create-pipeline --pipeline file://pipeline.json
# pipeline.json defines three stages, each backed by a real service:
#   Source  -> CodeStar connection to GitHub, triggers on push to main
#   Build   -> CodeBuild project running the buildspec above
#   Deploy  -> CodeDeploy (or ECS/EKS deploy action) using imagedefinitions.json

This is the AWS-native equivalent of the GitHub Actions workflow you'll build next week — same three logical stages, different vendor. Building both gives you a real basis for comparison instead of a guess.

2CodeArtifact for package and dependency management

Create a repository and point pip/npm at it
aws codeartifact create-domain --domain roadmap
aws codeartifact create-repository \
  --domain roadmap --repository roadmap-packages

aws codeartifact login --tool pip --domain roadmap --repository roadmap-packages
pip install requests   # now resolves through your private, cached CodeArtifact repo
Checkpoint

Point CodeArtifact's roadmap-packages repo at the public PyPI as an upstream, then confirm a package installs even the first time (proxied through CodeArtifact and cached) — that caching layer is what protects you when a public registry has an outage.
