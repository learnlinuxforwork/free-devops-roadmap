1S3 lifecycle policies, replication, storage class analysis

Lifecycle policy — age data down to cheaper storage automatically
{
  "Rules": [{
    "ID": "archive-old-logs", "Status": "Enabled", "Filter": {"Prefix": "logs/"},
    "Transitions": [
      {"Days": 30, "StorageClass": "STANDARD_IA"},
      {"Days": 90, "StorageClass": "GLACIER"}
    ],
    "Expiration": {"Days": 365}
  }]
}
Apply it, and turn on cross-region replication for disaster recovery
aws s3api put-bucket-lifecycle-configuration \
  --bucket roadmap-capstone-<yourname> --lifecycle-configuration file://lifecycle.json

aws s3api put-bucket-replication --bucket roadmap-capstone-<yourname> \
  --replication-configuration file://replication.json

Storage class analysis (in the console under Management -> Storage class analysis) watches actual access patterns for 30+ days and recommends which prefixes are good lifecycle candidates — don't guess at transition days, let the data tell you.

2FSx and Storage Gateway use cases — know when to pick what

FSx family — pick by workload, not by habit
FSx for Lustre       High-performance computing, ML training, needs S3 integration
FSx for OpenZFS      POSIX filesystem semantics, snapshots, needs NFS compatibility
FSx for NetApp ONTAP  Migrating existing NetApp workloads, needs multi-protocol (NFS/SMB)
Storage Gateway — bridge on-premises storage to AWS
File Gateway     On-prem NFS/SMB share backed by S3 objects
Volume Gateway    iSCSI block volumes, cached or stored mode, backed by EBS snapshots
Tape Gateway      Virtual tape library — replace physical backup tape with S3/Glacier
Checkpoint

For a given exam-style scenario ('an on-prem app needs an NFS mount that looks local but is backed by cloud storage'), name the exact service in under 10 seconds — File Gateway. That kind of pattern-matching is most of what SAA-C03 storage questions test.
