1HCL syntax, providers, resources, variables, outputs

A minimal but complete Terraform config
# providers.tf
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}
provider "aws" { region = var.aws_region }
Variables — never hardcode what changes between environments
# variables.tf
variable "aws_region" {
  type    = string
  default = "us-east-1"
}
variable "instance_type" {
  type    = string
  default = "t3.micro"
}
A resource, and an output other configs (or you) can read
# main.tf
resource "aws_instance" "web" {
  ami           = data.aws_ami.al2023.id
  instance_type = var.instance_type
  tags          = { Name = "roadmap-week21" }
}

# outputs.tf
output "instance_public_ip" {
  value = aws_instance.web.public_ip
}
The core workflow
terraform init      # download providers, set up backend
terraform plan      # preview the diff between config and reality
terraform apply     # make it real
terraform destroy   # tear it down -- use freely in a learning sandbox
Checkpoint

Run terraform plan twice in a row with no changes in between and confirm it reports zero changes — that idempotency is the entire point of declarative IaC.

2State file mechanics; local vs remote state

Terraform's state file (terraform.tfstate) is the source of truth it uses to map your config to real resource IDs and detect drift. Losing it means Terraform no longer knows what it manages — it doesn't delete your infrastructure, but it can no longer safely change it.

Local state — fine solo, dangerous with a team
# default behavior, no config needed -- state lands in ./terraform.tfstate
# problem: no locking, no shared source of truth, easy to lose or leak secrets in plaintext
Inspecting state directly
terraform show                       # human-readable dump of current state
terraform state list                  # every resource Terraform is tracking
terraform state show aws_instance.web # detail on one resource
terraform refresh                     # reconcile state with real infrastructure
Common trap

State files often contain secrets in plaintext (a generated RDS password, for instance). Never commit terraform.tfstate to Git — add it to .gitignore immediately, even before you set up remote state next week.
