1Transit Gateway, VPC peering at scale, Site-to-Site VPN, Direct Connect concepts

Transit Gateway — a hub for many VPCs instead of a peering mesh
aws ec2 create-transit-gateway --description "roadmap-hub"
aws ec2 create-transit-gateway-vpc-attachment \
  --transit-gateway-id tgw-xxxx --vpc-id vpc-aaaa --subnet-ids subnet-aaaa
aws ec2 create-transit-gateway-vpc-attachment \
  --transit-gateway-id tgw-xxxx --vpc-id vpc-bbbb --subnet-ids subnet-bbbb

Peering connections don't transitively route — a peers to b, b peers to c, but a still can't reach c without its own direct peering connection. That's exactly the problem Transit Gateway solves: one hub, every attached VPC can route through it.

Site-to-Site VPN — encrypted tunnel to an on-prem network
aws ec2 create-customer-gateway \
  --bgp-asn 65000 --public-ip <ON_PREM_PUBLIC_IP> --type ipsec.1
aws ec2 create-vpn-gateway --type ipsec.1
aws ec2 attach-vpn-gateway --vpn-gateway-id vgw-xxxx --vpc-id vpc-xxxx
aws ec2 create-vpn-connection \
  --customer-gateway-id cgw-xxxx --vpn-gateway-id vgw-xxxx --type ipsec.1

Direct Connect is a dedicated physical network circuit into an AWS facility — there's nothing to provision via CLI in a home lab; it exists to replace VPN's internet-dependent, variable-latency path with a private, consistent one for high-throughput workloads. Know it for the exam; you won't build it here.

2Route 53 routing policies and health checks

Hosted zone and a health check
aws route53 create-hosted-zone \
  --name roadmap-app.example.com --caller-reference $(date +%s)

aws route53 create-health-check --caller-reference $(date +%s) \
  --health-check-config '{
    "IPAddress": "203.0.113.10", "Port": 443,
    "Type": "HTTPS", "ResourcePath": "/healthz"
  }'
Weighted routing — canary a new version to 10% of traffic
aws route53 change-resource-record-sets --hosted-zone-id Z123 \
  --change-batch '{
    "Changes": [{"Action": "UPSERT", "ResourceRecordSet": {
      "Name": "app.example.com", "Type": "A", "SetIdentifier": "v2-canary",
      "Weight": 10, "TTL": 60, "ResourceRecords": [{"Value": "203.0.113.20"}]
    }}]
  }'

Other policies worth knowing cold for the exam: latency-based (route to the region with lowest latency for that user), failover (active/passive, driven by a health check), and geolocation (route by the requester's location).

Checkpoint

Attach the health check to a failover record pair, then stop the primary target and confirm Route 53 fails traffic over automatically within a couple of minutes.
