1Pods, Deployments, Services, Namespaces, ReplicaSets

A Deployment — you almost never create a bare Pod directly
apiVersion: apps/v1
kind: Deployment
metadata:
  name: roadmap-api
  namespace: roadmap
spec:
  replicas: 3
  selector:
    matchLabels: { app: roadmap-api }
  template:
    metadata:
      labels: { app: roadmap-api }
    spec:
      containers:
        - name: api
          image: <ACCOUNT_ID>.dkr.ecr.us-east-1.amazonaws.com/roadmap-api:v1
          ports: [{ containerPort: 8080 }]
A Service — stable network identity for a set of Pods
apiVersion: v1
kind: Service
metadata:
  name: roadmap-api
  namespace: roadmap
spec:
  selector: { app: roadmap-api }
  ports: [{ port: 80, targetPort: 8080 }]

The chain is: a Deployment manages a ReplicaSet, which ensures N Pods matching a label selector are running. A Service is a separate stable endpoint that load-balances across whatever Pods currently match its own selector — Pods come and go, the Service's ClusterIP doesn't.

2kubectl fluency; run a local cluster with kind or minikube

Local cluster
kind create cluster --name roadmap
kubectl cluster-info --context kind-roadmap
kubectl create namespace roadmap
Apply and inspect
kubectl apply -f deployment.yaml -f service.yaml
kubectl get pods -n roadmap -o wide
kubectl describe pod <pod-name> -n roadmap
kubectl logs -f <pod-name> -n roadmap
kubectl exec -it <pod-name> -n roadmap -- /bin/sh
kubectl port-forward svc/roadmap-api 8080:80 -n roadmap
Delete and clean up
kubectl delete -f deployment.yaml -f service.yaml
kind delete cluster --name roadmap
Checkpoint

Scale the Deployment to 0 and back to 3 with kubectl scale, and kill a Pod directly with kubectl delete pod — watch the ReplicaSet replace it within seconds without you doing anything else.
